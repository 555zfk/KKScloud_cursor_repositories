# 人形机器人本体设计流程

覆盖整机设计的九步流程与其中的载荷分析方法。电机选型（TN 曲线、效率、功率）由
`关节需求计算agent操作流程` 技能承担，本技能只在步骤③④⑤处引用，不重复实现。

## 九步流程

| 步骤 | 内容 | 本技能提供的方法 |
|---|---|---|
| ① | 构建简化三维模型，依候选模组推测质量及 TN 数据，覆盖每个 link 质量惯量属性，导出简化 URDF | — |
| ② | 按预测赋值 armature、摩擦等数据；Isaac/MuJoCo 仿真各预期动作姿态，导出关节扭矩/转速 CSV 与六维力 | 见「仿真参数必须先标定」 |
| ③ | 分工况统计各关节峰值/RMS 扭矩转速，形成 TN 散点与包络曲线 | 载荷可信性判据（先清洗再统计） |
| ④ | 按效率曲线反推全过程功率，得 RMS 电机输入功率 | 引用 `关节需求计算agent操作流程` |
| ⑤ | 汇总各 joint 额定扭矩/转速/功率**与倾覆力矩**需求，收敛模组型号，形成设计需求 | 六维力分解 + 轴承校核 |
| ⑥ | 正向设计关节模组，取模组质量属性与尺寸，**复核质量变化** | 质量螺旋收敛判据 |
| ⑦ | 依模组数据完成详细整机结构设计 | — |
| ⑧ | 制作详细 URDF，再次仿真复算 | 与①的载荷对比，判断是否需回到⑤ |
| ⑨ | 实机验证 | — |

## 流程本身的三个结构性风险

写方案或评审流程时必须点出这三条，它们不是执行细节而是流程缺陷：

1. **effort_limit 循环论证**：②的仿真需要给定关节扭矩上限，而这个上限本应是⑤的输出。
   若①的预测值偏大，RL 策略会学出依赖大扭矩的动作，⑤便得到虚高需求。
   对策：①用候选模组的真实 TN 包络而非拍定的单一数字，并在⑧用实际模组包络复算，比较动作是否仍可行。
2. **质量螺旋**：⑥的模组比①预测的重 → ⑦整机变重 → ⑧载荷上升 → 需要更大模组。
   对策：⑥必须显式复核质量偏差，设定阈值（如单模组 +15% 或整机 +8%）触发回到⑤，而不是直接进⑦。
3. **仿真参数未标定**：②的 armature、关节摩擦、接触刚度/阻尼若只是"按预测赋值"，
   ③得到的峰值就没有物理依据。对策见下节。

## 仿真参数必须先标定（步骤②）

按优先级标定，未标定项要在报告里注明为假设值：

- **armature（反射惯量）**= 转子惯量 × 减速比²，可由候选模组样本直接算出，属可信项。
- **关节摩擦**：库仑 + 粘性，来源是模组实测拖动力矩；无实测时按同类模组取值并做 ±50% 敏感性分析。
- **接触刚度/阻尼**：决定落地峰值的量级，是所有参数里对峰值影响最大且最难标定的一项。
  没有实测就不要把落地峰值当定量结论用。
- **控制带宽/延迟**：RL 策略常隐含无限带宽，实机做不到，会导致仿真峰值偏高。

RL 策略会主动利用仿真的理想化（无背隙、无延迟、接触刚度理想），
所以③统计出的峰值必须先过可信性判据。

## 载荷可信性判据（步骤③前置）

统计任何峰值前先做这三步，详见 [载荷可信性判据.md](载荷可信性判据.md)：

1. **看上升过程**：峰值若在 1 个采样步内建立，即为欠解析，只能作定性参考。
2. **分因**：看同时刻执行器扭矩变化率。变化率超出实机电流环能力（量级 >100 kN·m/s）
   说明是控制跳变假象；变化率正常而接触力骤升则是欠解析的地面冲击。
3. **取统计量而非极值**：选型用 **p99**，寿命用 **立方平均**，峰值仅作定性参考。

## 带腾空相的动作：载荷只能用逆动力学取（步骤②③）

跑步、跳跃这类有腾空相的动作，**不要指望从闭环仿真里读载荷**。腾空那段没有支撑点，
基座六个自由度全部不可控，位置伺服（乃至任何不做落地阻抗和腾空姿态规划的控制器）
都会摔。摔倒过程量到的力矩往往**比正常载荷还大**，一旦混进选型表就会把模组选大一档，
而且很难被发现——数字看着"合理"，只是物理上毫无意义。

判据很简单：**看基座高度和质心跟踪误差**。基座掉到初始高度一半以下，或质心脱离参考
轨迹半米以上，整张表作废。这个检查应当写进报表脚本自动执行，不要靠人看。

正确做法是对规划轨迹做逆动力学。给定位形、速度、加速度和地面反力，各关节需要多大
力矩是**代数确定**的，不需要闭环稳定：

τ = M(q)q̈ + C(q,q̇) + G(q) − Σ Jᵢᵀ Fᵢ + D q̇

MuJoCo 里用 `mj_rne(m, d, 1, out)` 算前三项（需先 `mj_kinematics` → `mj_comPos` →
`mj_comVel`），接触力用 `mj_jac` 在压力中心处取雅可比自己减。

### 四个必须做的检查

这类反推没有仿真的"跑得起来"作背书，全靠自检兜底：

1. **静力自检**：取动作开始前的静立段，浮动基那 6 行残差必须**接近零**。不为零说明
   管线错了（重力符号、质量、接触点位置），后面所有数都不用看。注意静立时把体重
   平分到两只脚是**错的**——合力必须过质心的地面投影，否则凭空多出一个倾覆力矩。
2. **独立复核**：在地面反力最大那一帧，绕目标关节轴做一次纯静力矩平衡
   （τ = â · ((cop − anchor) × F)），和逆动力学结果比。差值应当等于该关节以下
   连杆的惯性项（量级几 N·m）。对不上说明有一边错了。
3. **浮动基残差分相统计**：残差是"规划把整机当质点"与真实多体的差账，落在躯干和
   摆臂上。**腿部力矩不吃这笔账**——末端关节力矩由足底反力和其下连杆惯量从末端往回
   递推，与浮动基那 6 行无关。所以躯干残差大不影响腿部结论，但要在报告里写明。
4. **峰值 vs p99 同时给**：两者接近的是真需求；峰值远高于 p99 的是轨迹折点被二阶
   差分放大的假尖峰。选型看 p99。

### 微分噪声

轨迹要被二阶差分成加速度，**逆解的收敛门槛必须压到亚纳米**。1 µm 的逐帧抖动除以
dt²（4 ms）就是 0.06 m/s²，几十个关节攒起来能在浮动基上凑出十几牛的假残差。
不动点迭代每轮降一个数量级以上，多迭代几次很便宜。

采样也要一致：地面反力峰值若有几倍体重、几十毫秒内起落，斜率能到 10⁴ N/s 量级，
**按最近邻取值一个采样的错位就是几十牛**，看着像动力学不自洽，其实只是取值取歪了。
用线性插值。

必要时再加零相移的 Savitzky–Golay 微分（局部三次拟合，窗宽取支撑相的四分之一），
但先修收敛门槛和取样，不要拿滤波去盖真实的建模错误——**滤波压不下系统性偏差**，
静力自检不过就说明问题不在噪声。

### 跑跳的峰值载荷由 duty 决定，不由速度决定

反推跑步/跳跃需求时最容易做错的判断是「跑慢点就够了」。竖直冲量必须在一个步周期
内平衡重力，半正弦反力于是给出

    Fz_peak / mg = (π/2) / duty        （duty = 触地时间 / 步周期）

**峰值地面反力只由 duty 决定，与速度无关**；而中支撑时膝的力臂由蹲姿几何定死，
也基本与速度无关。两者相乘，膝扭矩就与速度无关。实测某 17 kg 机型速度从 0.8 翻到
2.0 m/s，膝 p99 稳定在 83~85 N·m 纹丝不动，**只有转速需求随速度涨**。

推论：**降速只能救转速，救不了扭矩**。duty 又被腾空相卡在 <0.5（≥0.5 就是走不是跑），
所以峰值反力有个下界 π/2 ≈ 1.57 倍体重，实际取 duty 0.35~0.48 就是 3.3~4.5 倍。
扭矩不够时，能动的只有：加并联弹簧卸掉支撑相的保守功（SLIP 的压缩-回弹本来就是
保守过程，这是唯一能同时压低峰值和 RMS 的办法）、换更大模组、或减重。调步态没用。

选型时注意**连续扭矩往往比峰值更难满足**：峰值可以靠短时过载扛，连续超两三倍是
散热问题。

### 反推跑跳载荷时，蹲姿深度是比速度大一个量级的杠杆

膝（以及一切中间关节）的力矩 = 地面反力 × 力臂，上一条说了反力与速度无关，**所以
真正能调的是力臂**。对等长的大小腿，膝偏离髋-踝连线的距离 = √(L² − (d/2)²)，d 是
髋到踝的距离。这个函数在腿接近伸直时导数极大：L=200 mm 时 d 从 350 涨到 380 mm，
力臂就从 96.8 掉到 62.4 mm，掉 36%。

所以反推需求时**必须把预蹲深度也扫进去，而且它常常是主效应**。上例把预蹲从 70 mm
压到 28 mm、duty 从 0.35 提到 0.48，膝的缺口从「峰值 ×2.1 / 连续 ×3.1 / 转速 ×1.9」
变成「峰值 ×0.99 / 连续 ×1.7 / 转速 ×1.7」——峰值直接进规格。只扫速度会得出
「任何参数都差 ×2.8、必须换模组」的过悲观结论。

浅蹲有两个反向约束，扫的时候会自己撞上，别硬调：

- **水平可达范围随腿伸直而缩**，步长被压短，高速时步频被迫飙升，转速反而恶化
  （上例预蹲 20 mm、2 m/s 时步频 12.5 Hz，转速需求从 ×1.7 炸到 ×2.3）。
- **支撑相质心还要下沉十几毫米**，浅蹲时直接顶到全伸，逆解够不着而发散。

因此存在一个极小值，用逆解残差发散作为下边界去逼近它即可（上例极小值在 28~30 mm，
25 mm 已发散）。注意「载荷可行」不等于「控得住」——贴着奇异点的蹲姿，支撑相雅可比
条件数会变成控制上的新麻烦，这一条要在结论里写明。

### 步频要由腾空时长定，不能由步长定

规划跑步时若按「落脚角 × 腿长」把步长定死、再用 f = v/步长 反推步频，低速会崩：
步长与速度无关，速度一降步频就掉，腾空时长拉长，而弹道抬高 g·t_f²/8 按平方涨，
腿长却是死的。上例 1.0 m/s 时步频掉到 3.12 Hz、腾空 208 ms、质心起伏 174 mm，
388 mm 的腿根本够不着地，规划直接发散。

正确做法是反过来：**用腾空时长上限定住步频下限，步长 = v/f 随速度走**，只有速度
高到步长够不着时才由几何上限顶着提步频。这也是动物的规律（人从 2 到 5 m/s 步频
只涨约 20%，主要靠加步长）。注意几何上限要用**舒适步长**（落脚角推出来的），
不能用腿完全伸直的跨距——那正好是逆解奇异点。

### 起跑的侧向瞬态要预置，不能靠反馈抓

站立时两脚分开、质心居中，第一条支撑腿的压力中心只能是它当前站的位置，一落地
就是「半脚距力臂 × 数倍体重」的侧向推力。侧向落脚点控制器的行程有限（落脚点不能
无限外放），抓不住这个瞬态，低速档尤其危险——触地时间越长，侧向每步的发散特征值
越大（上例 56 ms 时 2.23，64 ms 时 2.50）。

对策不是放宽落脚点夹限，而是**起跑前就把质心侧向挪到位**：反解出「过完第一步正好
落在周期轨道上」所需的触地状态，用双脚支撑的半秒把质心送过去。注意脱离地面后
没有横向力，挪动必须在离地前完成，最后的自由落体段只能匀速滑过去。

## 六维力与倾覆力矩（步骤⑤）

关节倾覆力矩是垂直于回转轴的合成弯矩，**与坐标系选择无关**：

M_perp = |M − (M·â)â|，其中 â 为关节回转轴单位向量

倾覆力矩是纯约束反力，必须由关节轴承与减速器输出端全部承担，
因此比六维力的轴向分量更可靠（轴向分量含阻尼、摩擦、限位约束与闭链杆件力，不等于执行器扭矩）。

运行 `python wrench_decompose.py`（先改顶部 USER CONFIG）得到轴向扭矩、倾覆力矩、
径向力、轴向力的时程与统计。数据约定校准方法见
[六维力与倾覆力矩分析.md](六维力与倾覆力矩分析.md)。

## 轴承与减速器输出端校核（步骤⑤⑥）

**倾覆能力常先于电机扭矩成为瓶颈**，典型比例是倾覆力矩为轴向扭矩的 2～2.5 倍，
所以关节模组设计需求里必须单列倾覆力矩一项，不能只写扭矩/转速/功率。

交叉滚子环按 THK 样本 515-1E：

- 静等价径向载荷 P0 = Fr + 2M/dp + 0.44·Fa
- 静态安全系数 fs = C0 / P0，普通载荷 ≥2、冲击载荷 ≥5、推荐 ≥7
- 静许用倾覆力矩 M0 = C0·dp/2（这是 fs=1 的损伤临界值，**不是设计许用值**）

运行 `python crossed_roller_check.py` 完成校核。公式出处、双轴承跨距分析与算例见
[交叉滚子轴承校核.md](交叉滚子轴承校核.md)。
